\section{任务定义与评估 从一次失败开始}\label{任务定义与评估 从一次失败开始}

我们把一道题交给模型：``请解方程 3(a＋2)＝21，并解释每一步。''我们期待它先除以 3，再减去 2，得到 a＝5。它却接着写：``这是初中代数教材中的一道基础题，下面还有几道同类练习。''句子很通顺，也与题目有关，但它没有完成任务。

如果先给模型一段问答示例，再把同一道题放在末尾，它也许就能给出正确答案。此时，算力和参数都没变，变化的是上下文。这个例子可以从三个层面分析：模型掌握了哪些知识，当前提示怎样影响生成，以及生成的回答怎样对应用户的任务。

基座语言模型学习的是文本延续规律。真实语料里，问题后面可以接答案、题目分析、引用或另一道题。提示中的问答格式与示范为模型提供了续写线索，引导它从多种可能的延续方式中生成解题回答。

在训练之前，我们通常先写一份小型验收约定。我们选出四类需求：讲清基础题；回答课程资料问题；在缺少资料时说不确定；通过计算器处理容易算错的数值。每类需求对应具体的检查项：解题任务分别检查结果和推导步骤，资料问答分别检查引用来源和引用内容对回答的支持程度。

数据可以按用途分为三份。训练集用来更新参数；验证集用来选提示、超参和检查点；最终测试集用于评估确定后的方案。划分时以母题为单位，将同一道题的改写版本放在同一份数据中。

在快速迭代中，研发人员也会根据固定题集上的表现合成训练数据、调整训练方案。这份题集承担的是开发评估职能。方案确定后，再用预先留出的独立测试集评价最终效果。

从这一步起，评估围绕具体任务展开：各类题目的正确率怎样变化，推导步骤是否完整，资料引用是否准确，完成一次任务需要多少计算预算。这份最初的评估约定，也用于定位监督微调（Supervised Fine-Tuning，SFT）续训和强化学习（Reinforcement Learning，RL）中的问题。SFT 用示范回答训练模型，RL 则依据反馈优化模型的尝试；我们稍后会逐步展开。

\section{训练阶段 语言学习类比能解释什么}\label{训练阶段 语言学习类比能解释什么}

为了理解接下来发生的事，我们先想象一个熟悉的过程。婴儿长期听到周围的人说话，逐渐熟悉声音与表达；后来在互动中练习表达，得到示范和反馈。这能帮助我们建立一个入口：大量接触语言、学习具体表达、再依据结果调整，是相互衔接的三个学习环节。

我们可以把预训练类比为广泛接触语言，把监督微调类比为有人示范``面对这个问题，可以这样回答''，把反馈学习类比为比较不同回答是否合适。沿着这个学习过程，可以理解不同训练阶段的数据来源与反馈方式。

落实到计算过程，文本语言模型的预训练通常是在已有序列上预测下一个词元（token，即分词后的基本处理单元），并通过预测误差更新参数。SFT 也常使用逐 token 交叉熵（cross-entropy）损失，在指令与回答组成的数据上训练。两者的重要区别在于数据的组织、监督的位置和希望强化的行为分布\footnote{大模型根据上下文计算下一个 token 的概率分布，再通过采样等解码方式选出下一个 token。}。后文讨论模型的``行为''时，会反复从输出分布的角度分析它。

预训练得到的参数决定了模型怎样根据上下文计算 next token 分布。对于同一道题，在题目前加入解题指导，就改变了模型生成答案时的条件输入，相应的输出分布也会变化。调整上下文和更新参数，是影响模型行为的两种方式。

后训练以已有模型为起点，通过示范或反馈继续调整参数。较大规模的后训练可以覆盖多类任务，小规模后训练则可以围绕某个领域或具体行为组织数据。例如，在别人已经训练好的模型上，用少量领域问答继续做 SFT，或用任务奖励进行 RL 训练。沿用学习的类比，一个人系统学习了四年中国哲学，随后学习西方哲学，新知识会与已有的概念体系建立联系，并影响他分析问题的方式。

不妨想象模型对一道题能给出三种回答。训练前，它有时直接给答案，有时续写题目，有时解释步骤。SFT 用高质量示范提高相应解题流程的生成概率；RL 则依据奖励调整不同尝试的概率。例如，同一道题尝试 10 次，其中 2 次答对，训练便可以利用这两条成功轨迹的反馈，提高模型生成有效解法的概率。前者提供可学习的轨迹，后者利用模型自己的尝试选择和强化求解路径。

观察这些变化时，可以固定输入、解码设置与采样预算，多次生成回答，比较训练前后直接作答、续写题目和分步求解的出现频次。这样就把模型的行为变化与输出分布联系起来，也为后面的训练实验建立了观察方法。
