\chapter{检索 工具与系统评估}\label{检索 工具与系统评估}

\section{检索增强生成 RAG 让回答获得外部依据}\label{检索增强生成 RAG 让回答获得外部依据}

小助能解方程，却不知道``本周作业最晚何时提交''。这不是我们希望通过长推理猜出来的答案。课程规则在变化，部分信息又是私有的，我们决定让小助先找资料，再根据证据回答。

RAG 的核心是把检索到的外部材料纳入生成条件。参数里的知识依然有用，但这次回答的具体依据来自可更新的资料库。RAG 可以改善信息可得性和来源追踪，却不自动保证没有幻觉：检索会漏，资料会错，模型也会错误解读或引用。

我们先把课程文件切成段落。固定长度很简单，但可能把``允许迟交''和``超过多久不计分''拆开。我们结合标题、段落、表格与适度重叠，让每个 chunk 保有必要上下文，同时保存文档名、版本、页码或段落编号。重叠过多会增加重复检索，切得太大又会把相关句子淹没在噪声里，因此要用查询与证据覆盖率选择。

接着，我们用第三部分的嵌入模型编码文档，建立索引；收到查询后编码问题，召回一批候选。若课程名称或作业编号很关键，可以同时做最佳匹配 25（Best Matching 25，BM25）等词法检索，再融合结果。向量擅长语义联系，词法方法对精确字符串常有优势，二者是否互补仍要看任务。

召回后，我们可用交叉编码器（cross-encoder）重排。双塔嵌入先把查询和文档分别编码，便于大规模比较；cross-encoder 让查询与候选一起进入模型，进行更细的相关性判断，代价也更高。我们因此用它处理有限候选，而不是直接对整个资料库逐条运行。

最后，我们把少量证据与问题一起交给小助，要求回答中标明依据，证据不足时说明缺口。资料是待阅读的数据，不是有权改写系统规则的指令。系统还应在检索前执行访问权限约束，避免把用户无权访问的内容放进上下文。模型再聪明，也不能替代这层权限控制。

图 \ref{fig:RAG证据链} 将离线建库与在线回答分成两条路径。离线索引保存可检索的表示与来源，在线过程才根据这次问题选择证据。最后的核查不是一句``请保证正确''，而是逐条判断答案的陈述是否得到证据支持。

我们完成的不是一条``向量库接聊天框''的捷径，而是一条可逐段检查的证据链：正确材料存在吗，切分保留了吗，召回找到了吗，重排留下了吗，生成忠实使用了吗？下一节就沿这条链定位失败。

\textbf{停下来试一试} 用二十条自建课程规则做最小 RAG。其中一条保留两个版本，一条明确未提供答案。检查系统是否选择有效版本、正确引用，以及是否在未知问题上停止猜测。

\textbf{本节相关资料}
\begin{enumerate}
    \item Lewis 等，2020，\href{https://arxiv.org/abs/2005.11401}{Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks} 。阅读重点：参数化知识与外部检索如何结合。现代工程 RAG 并不都照搬原论文训练结构。
    \item Nogueira 与 Cho，2019，\href{https://arxiv.org/abs/1901.04085}{Passage Re-ranking with BERT} 。阅读重点：联合编码查询与文档为什么适合重排。
\end{enumerate}

\section{RAG 诊断 沿证据链定位失败}\label{RAG 诊断 沿证据链定位失败}

我们问``作业允许迟交几天''，小助引用了一段相关资料，却答错限制条件。只看最终答案，我们不知道该换嵌入模型、扩大上下文，还是重训生成器。我们于是为每个失败保存完整过程：查询、候选、分数、选入上下文的证据和最终回答。

第一步做 oracle context 实验：直接把人工确认的正确证据交给生成器。如果这时仍答错，优先检查阅读、提示、冲突处理或任务能力；如果这时答对，问题更可能在前面的检索与组织。这个实验不证明生成器在所有输入上无错，但可以快速分开两大类瓶颈。

随后逐段检查。正确证据不在资料库，是信息缺失；原文有而 chunk 不完整，是切分问题；穷举相似度能找到、ANN 找不到，是索引召回问题；召回中有、重排后丢了，是重排问题；上下文中有、答案仍歪曲，是生成使用问题。我们一次只替换一个组件，避免把全部管线重写后失去解释。

若查询太短或术语错位，可以尝试查询改写。假设文档嵌入（Hypothetical Document Embeddings，HyDE）先生成一个假设性文档，再用它做检索桥梁；假设文档的内容可能并不真实，它的用途是帮助定位相关材料，不能作为回答证据。我们始终以实际检索到的原始资料为依据。

若用户问的是整套课程材料的共同主题，单段检索可能不够。图检索增强生成（Graph Retrieval-Augmented Generation，GraphRAG）等方法尝试把实体、关系或社区摘要组织起来支持更全局的问题，但增加了建图、更新和评估成本。若需要多轮查找，可以采用智能体式检索增强生成（agentic RAG），让系统根据已有结果继续检索；每多一步也增加偏航与延迟的可能。

有同学会提议直接放完整资料进长上下文。对于规模可控、需要跨段联系的资料，这可能是好基线；但上下文容量不等于稳定利用能力，长输入还增加成本。我们实际比较 RAG、长上下文和二者组合，而不是先选一个时髦名词。

\section{提示与智能体 从表达要求到工具调用}\label{提示与智能体 从表达要求到工具调用}

学生提出一道带小数的复杂计算。小助会解释思路，却在最后一位出错。继续收集千条同类训练数据之前，我们先问：能否把计算交给可靠工具，让模型负责理解任务与组织结果？

我们先设计清楚的提示。system 说明任务规则，user 提供问题，assistant 产生回答；这些角色要经过对应 chat template 才成为模型输入。few-shot 示例展示所需行为，明确输出结构规范（schema）便于程序检查。提示不更新参数，却改变条件上下文，因此可以明显改变回答分布。它能唤起已具备的行为，也可能因含糊、冲突或上下文过长而失效。

工具调用（function calling）进一步把输出解释为动作。小助产生工具名和参数；常见载体是 JavaScript 对象表示法（JavaScript Object Notation，JSON）一类结构化格式。外部程序验证 schema、检查权限、执行并返回结果，模型再根据结果继续。结构正确是第一道门槛，参数是否符合任务、工具是否真正执行、结果是否被忠实使用是后续门槛。生成一段看起来像 JSON 的文本并不等于动作已经发生。

推理与行动方法（Reasoning and Acting，ReAct）帮助我们把推理与行动交替组织。我们在实现中保存任务状态、工具返回和关键约束，让系统在观察新证据后选择下一步。这里不必把模型所有内部推演展示给用户；外部可审计记录应包含动作、输入、返回、错误与决策结果。用户需要可检查的进展与依据。

我们也不把工具调用能力全部归功于某一种 SFT。提示示例、监督数据、执行反馈、合成训练都可能帮助形成该行为。对应用开发者，更直接的问题是接口是否支持、参数是否可靠、失败后能否恢复。复杂智能体（agent）框架不能替代这些基础能力。

第一次实验，我们只提供两个工具：检索课程规则与计算器。系统设置最大步数、超时与重试上限，要求在工具失败时说明状态。对于会产生现实写入的动作，由应用执行清楚的权限与必要确认；模型不能因为读到一段资料里的命令就获得额外权限。外部内容与系统指令的边界，也是任务可靠性的一部分。

我们发现长任务还有上下文管理问题。工具返回太长，旧约束被挤掉；摘要太激进，关键条件丢失。我们保留原始日志和结构化状态，在压缩上下文时验证必要字段。一个可恢复的小循环，往往比一开始追求自主完成几十步更适合学习。

\textbf{停下来试一试} 给小助接上两个只读工具，测试正常调用、参数错误、工具超时和返回无结果四种情况。逐步记录它是否重试、是否编造成功、是否能停止。成功路径之外，恢复路径同样需要设计。

\textbf{本节相关资料}
\begin{enumerate}
    \item Yao 等，2022，\href{https://arxiv.org/abs/2210.03629}{ReAct Synergizing Reasoning and Acting in Language Models} 。阅读重点：动作与外部观察怎样改变后续决策。
    \item Schick 等，2023，\href{https://arxiv.org/abs/2302.04761}{Toolformer Language Models Can Teach Themselves to Use Tools} 。阅读重点：工具使用训练可以怎样构造数据与反馈。
\end{enumerate}

\section{分层评估 怎样证明系统真的变好}\label{分层评估 怎样证明系统真的变好}

从最初续写题目到现在，小助已经经历多种训练，也接上资料和工具。如果此刻只展示几个成功演示，我们仍然没有证明它可靠。我们回到第一节的验收约定，把模型能力和系统能力分别测清楚。

模型层评估包括固定题目的答案、解释和指令遵循；检索层包括相关证据是否召回、重排是否保留；系统层还要看工具执行、引用支持、延迟与失败恢复。一个系统得分下降，可能是模型变差，也可能是资料版本或工具接口变化。分层测量让我们知道变化发生在哪里。

我们把常用基准当成观察窗口，而不是能力全貌。知识问答、数学、代码和人工偏好各测一部分；语言与任务分布不同，也可能改变结果。训练过程中若反复使用某个公开基准做选择，就更需要独立的自建题集确认迁移。我们保存数据来源和去重规则，检查是否意外含有评测答案。

开放回答可以做成对盲评，随机交换左右位置，允许平局，并给出清楚的质量维度。模型评审能降低成本，但可能偏爱长度、特定风格或与自己相近的回答。我们用一部分人工标注校准评审，检查不同子任务的误差。一个评审器总体相关不错，也可能在最重要的失败类型上不可靠。

统计上，我们报告分母与变化幅度。假如只有二十道题，多答对一道就变化五个百分点，不能过度解读。我们可以对同题的新旧结果做成对分析，用 bootstrap 等方法估计不确定性；若多次尝试后只挑最好结果展示，还要承认开发选择带来的乐观偏差。

我们最终选部署版本时，会同时考虑正确、可靠、可解释与成本。旧讲题能力不能因为新课规问答变好就消失；更长回答带来的分数，也要与时延比较。没有一个总分能自动替我们决定所有取舍，评价权重来自实际任务需求。

当新的失败到来，我们把它保存成带标签的案例，先确认属于信息缺失、行为偏移、探索不足、奖励偏差还是系统故障，再决定更新数据、训练或应用组件。这样，评估不只是结课考试，而成为系统继续学习的入口。

\textbf{停下来试一试} 设计一页评估报告，至少包含样本数、模型版本、固定解码配置、分项指标、成本和三个失败案例。遮住模型名称，请同学判断是否足以支持``值得替换旧版本''的结论。

\textbf{本节相关资料}
\begin{enumerate}
    \item Zheng 等，2023，\href{https://arxiv.org/abs/2306.05685}{Judging LLM-as-a-Judge with MT-Bench and Chatbot Arena} 。阅读重点：模型评审的偏差与人类偏好评估的设计。
    \item Chen 等，2021，\href{https://arxiv.org/abs/2107.03374}{Evaluating Large Language Models Trained on Code} 。阅读重点：执行评估与采样预算应怎样共同报告。
\end{enumerate}

\section{实践路线 六次连接全书的实验}\label{实践路线 六次连接全书的实验}

概念只有经过操作，才会变成可用的判断。我们把前八部分内容整理为六次实验，每次交付一个能解释的结果。算力不足时，我们可以使用更小模型、较少数据、现成检查点或离线日志，保留实验逻辑，不必为了规模跳过诊断。

第一次实验，我们训练一个玩具自回归模型。使用少量明确来源的文本，先划分训练与验证，再选字符级或现成 tokenizer，记录固定提示的生成变化。验收不是``它会写好文章''，而是我们能解释输入、目标、因果掩码与损失如何连接，能发现过拟合与数据问题。

第二次实验，我们建立一个小型课程资料库。用同一嵌入模型完成去重候选、聚类和检索，人工标注二十个查询的相关证据。验收时分别给出三类任务的错误，证明自己没有把几何接近误当成所有任务的正确标签。

第三次实验，我们用小模型做一次 SFT，再做一次可控续训。先制作高质量讲题示范，再加入偏短的新课程答案，观察旧任务变化；从同一起点比较回放、训练强度和数据风格。可以使用 Transformer 强化学习工具库（Transformer Reinforcement Learning，TRL）、LLaMA-Factory 等工具；后者是项目名称，不必展开成另一套缩写，但要记录版本并按相应官方文档配置。验收是分项收益与退化的证据，不是训练命令跑完。

第四次实验，我们做微型 RFT。对一批训练题多次采样，用可靠验证器筛选，抽查过程，再训练一次。与相同预算的原始 SFT 基线比较，报告题目覆盖、通过率、训练 token 与 留出评估结果。若有条件，再增加一个小规模 RLVR 实验；若没有，就用保存的奖励组分析零方差与探索瓶颈。

第五次实验，我们比较普通 SFT 与 DPO。用同一 SFT 起点和少量人工核对的偏好对，检查训练前后真实回答。特别加入长度相近但质量不同的样本，避免让长度替代质量。我们可以把 OPD 作为选做：只有在老师概率接口、tokenizer 对齐和预算都具备时才实施，否则先复核公开实验与估计器。

第六次实验，我们搭建最小 RAG，再接上计算器工具。保存每次检索与动作，加入无答案、资料冲突、工具超时等案例。最终测试使用未参与开发的新问题，并同时报告模型单独回答与完整系统回答。我们由此知道改进来自哪里，也知道系统仍在哪些地方会失败。

一个可行节奏是：前两周完成模型基础，第三周做表示，第四至五周做 SFT 与退化，第六至八周做采样、RFT、RL 诊断和偏好学习，最后两至四周完成推理与应用项目。我们按掌握程度调整，不把日历进度当作理解的证据。

\textbf{停下来试一试} 从六次实验中选一个，写出最小可执行规模、固定变量、唯一改动、验收指标和可能失败原因。若资源减少一半，说明先删什么，以及哪些诊断必须保留。

\textbf{本节相关资料}
\begin{enumerate}
    \item Brown 等，2020，\href{https://arxiv.org/abs/2005.14165}{Language Models are Few-Shot Learners} 。对应基础模型与上下文学习实验。
    \item Ouyang 等，2022，\href{https://arxiv.org/abs/2203.02155}{InstructGPT} 。对应示范、反馈与独立评估的串联。
    \item Lewis 等，2020，\href{https://arxiv.org/abs/2005.11401}{Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks} 。对应最后的知识增强系统。
\end{enumerate}

\section{研究闭环 从失败证据决定下一步}\label{研究闭环 从失败证据决定下一步}

回顾前面的学习时，我们重新打开第一天的题。小助现在能解释方程，也能依据课程资料回答截止时间，遇到信息不足时说明缺口。它仍可能失败，但我们已经能把失败变成下一轮工作，而不是只说``大模型有幻觉''或``再训练一下''。

如果它不知道一个新事实，我们先确认资料是否存在以及是否应该检索。如果它知道事实却不按要求表达，我们检查提示与示范。如果它偶尔成功却不稳定，我们测采样与选择，再考虑 RFT 或 RL。如果奖励涨而真实表现不涨，我们审查目标和泛化。如果训练完全无效，我们从最基本的信号链路开始。

我们也重新理解了最初的婴儿类比。广泛接触、示范练习、结果反馈，确实能帮助我们记住训练阶段之间的联系；真正指导工程的，则是每次输入、监督、分布与更新方式。故事让知识有位置，机制让位置不会误导我们。

一份合格的结课报告，应让另一组同学无需听我们的口头解释就能判断结果。我们写明任务、数据来源与切分、模型与模板版本、训练或检索改动、评价方法和成本；展示总体与分项结果；保存失败案例和可复现配置；最后只提出证据能够支持的结论。没有提升的实验也有价值，只要它排除了一个合理假设。

我们给下一阶段留一个研究题：在同样预算下，针对小助的一类具体缺陷，哪一种反馈最有效？我们可以比较增加示范、拒绝采样、偏好对和老师逐 token 反馈，但必须先控制起点、覆盖与预算。若无法同时控制，就明确哪些因素仍然混在一起，避免把数据收益误写成算法胜利。

到这里，整个体系已经接上了：预训练形成可生成的分布；表示学习支持数据组织与检索；后训练改变任务行为；采样与反馈重新分配成功路径；推理时计算增加尝试或过程；RAG 与工具提供外部信息和动作；评估再把失败带回数据与方法。我们以后遇到新论文，就把它放进这个循环，问它实际修复了哪里。

\textbf{停下来试一试} 不使用任何算法缩写，用一页文字复述``小助从第一天到现在''的经历。每出现一个新方法，都要先交代前一步暴露的具体问题。若某个概念找不到它要解决的问题，就回到对应小节补上上下文。
