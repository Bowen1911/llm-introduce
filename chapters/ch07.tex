\chapter{推理策略与推理时计算}\label{推理策略与推理时计算}

\section{思维链 CoT 与推理时计算}\label{思维链 CoT 与推理时计算}

训练告一段落，我们给小助一道需要多步转换的题。让它直接报答案时容易出错；让它先列出条件、写中间计算，再给结论，成功率可能提高。我们没有更新权重，却给了它更多生成过程。这就是思维链（Chain-of-Thought，CoT）与推理时计算（test-time compute）的入口。

自回归模型每生成一个 token，都进行一次依赖此前内容的计算。中间文字可以记录变量、拆解子问题、保留暂时结果，因此延长序列有时相当于把计算展开到更多步骤。但可见解释不是对内部机制的完整读出，模型也可能先偏向一个答案，再写出似乎合理的说明。我们评估步骤是否有效，不把流畅的长解释当成真实正确的证明。

我们还可以并行多试几次，再用选择器挑选。若题目有可规范化的最终答案，可以多数投票，这就是 self-consistency 的常见用法。它利用不同采样路径在答案上的一致性，却要求正确答案能形成足够支持。若模型反复犯同一种系统错误，多数投票反而会稳定选错。

另一种方式是多候选择优（best-of-N）：生成 N 个候选，由验证器或奖励模型选最好的。投票不需要评估每条步骤质量，选择器则可以利用更多信息，但会受到自身误差影响。若训练奖励曾被钻空子，我们不能未经验证就把同一个打分器当成完美选择器。

我们把三种方案放在相同预算下比较：一条长解答、几条短解答、多候选加验证。难题可能值得更多计算，简单题则无需长篇推导。若把更长输出全部视为进步，就会忘记用户需要的是及时而可靠的帮助。真正的曲线应当是任务质量相对于总 token、延迟和计算成本的变化。

训练 scaling 改变模型能力与分布，推理时计算则在给定模型上分配更多尝试或过程。它们可以互相补充，也可能受到不同瓶颈限制。模型若缺少必需知识，多想一会儿未必能补出来；若只是算术容易失误，调用计算器可能比再写一千 token 更有效。

\textbf{停下来试一试} 固定总生成预算，比较单条长回答、四条短回答投票和四条短回答加验证器。分别报告正确率、无效格式比例和平均延迟。解释为何不能只对比``单次短答''与``无限制多次长答''。

\section{推理模型 从示范和结果反馈到蒸馏}\label{推理模型 从示范和结果反馈到蒸馏}

观察到``多写步骤有时有用''，不等于模型已经学会稳定推理。小助可能把每题都写得很长，却重复同一句话；也可能在关键处跳步。我们要训练的是有效的推理行为，而不是某种看起来像思考的外观。

示范路线提供高质量解题轨迹，让学生学习分解、求解和检查；反馈路线让模型自己尝试，再依靠可验证结果或过程评价改进；蒸馏路线把强模型的解题数据或分布反馈交给较小学生。它们可以串联，也可以在不同阶段交替。对一个薄弱起点，先给有效示范常能改善后续探索；对已有丰富能力的起点，直接 RL 也可能发现新的有效行为。

DeepSeek-R1-Zero 的实验探索了从基座直接进行大规模 RL 的路线；R1 则使用冷启动数据和多阶段训练，处理可读性、语言一致性等需求。我们阅读时区分研究问题：前者展示特定起点与奖励条件下直接 RL 的可能性，后者展示面向更完整助手行为的组合管线。两者都不能被压缩成``只需 GRPO 就会自动推理''。

过程监督可以更细地评价中间步骤，结果监督则通常更容易自动获得。前者需要可靠的步骤标签或评审，后者可能把偶然猜中当成成功。我们可以抽查``答案正确但理由无效''和``中间合理但最后算错''两类样本，理解不同信号各自漏掉什么。

小模型学习强模型时，也有两种不同蒸馏。把老师完整解答做成数据再 SFT，是离线序列蒸馏；让学生自己生成、再查询老师分布，是第六部分的 OPD。长推理过程蒸馏并不天然等于 OPD。学生若模仿了复杂措辞却无法执行其中步骤，说明数据难度、表示能力或优化还需要调整。

我们还会遇到 thinking 与 non-thinking 模式。具体角色标记、开关和停止规则由模型定义，不能把某个产品接口当成所有模型的标准。实验时记录实际模板、是否允许生成推理段、推理预算与答案抽取方式；否则同一个模型也可能因为入口不同呈现完全不同的表现。

\textbf{停下来试一试} 让学生模仿一份过长且跳步的老师答案，再给一份更短但关键步骤完整的答案。先人工比较可学性，再决定如何制作训练集。老师答得对，不代表任何写法都适合当前学生学习。

\section{KV 缓存与推理服务 长上下文的资源成本}\label{KV 缓存与推理服务 长上下文的资源成本}

小助终于能认真解题，却让服务器变慢了。我们没有改参数，显存仍然迅速增长。原因之一是每个会话在生成过程中保留了越来越长的键值缓存（Key--Value Cache，KV Cache），后文简称 KV 缓存。

推理可分为预填充（prefill）和逐步解码（decode）。prefill 处理输入前缀，计算各层 key 与 value；decode 每轮生成一个新 token，查询此前缓存。缓存避免反复重算所有历史位置的 K、V，但不让历史读取变成零成本。随着上下文增长，每个新 token 需要处理的历史信息通常也更多。

图 \ref{fig:KV缓存复用} 接回第二部分的 QKV：进入新位置后，我们计算这个位置的新 Q、K、V；新 Q 读取缓存中的历史键值以及当前位置键值，完成注意力，再将当前位置 K、V 追加进缓存。历史位置在因果模型中不受后续 token 影响，因此相同前缀下可复用这些历史状态。这里画的是逐位置的数据依赖，具体算子可以把追加与读取融合执行。

    \label{fig:KV缓存复用}
\end{figure}

对一个简化的稠密注意力模型，单序列缓存占用可按两份张量、层数、KV 头数、头维度、序列长度与每元素字节数相乘估算。这里用 KV 头数而不是必然使用 query 头数，因为分组查询注意力（Grouped-Query Attention，GQA）等架构可能让多个 query 头共享 K、V。 用 M 表示字节占用，L 表示层数、H 的下标 KV 表示 KV 头数、d 表示头维度、S 表示缓存长度、b 表示每元素字节数，估算式为：
\[M_{KV} \approx 2\, L\, H_{KV}\, d\, S\, b\]

前面的 2 对应 key 与 value 两份缓存；该式按一个序列计算，多会话还要考虑并发，以及架构和缓存实现的差异。

例如 32 层、8 个 KV 头、每头 128 维、4096 个 token、每元素 2 字节，单序列 KV 约为 512 MiB。MiB 是二进制兆字节（mebibyte），1 MiB 等于 1,048,576 字节。这个教学估算还没算权重、临时缓冲、分配碎片和多个并发请求；实际系统也可能使用量化缓存、滑动窗口等不同机制。因此，我们把它当作量级检查，不当作完整容量规划。

FlashAttention 通过更好的计算与存储访问方式降低注意力的内存开销；PagedAttention 一类方案改善服务时的缓存管理。它们优化的是不同环节，也不等于任意长上下文都免费。我们观察首 token 延迟、每秒生成 token、并发吞吐和峰值显存，区分用户等待与服务器总效率。

部署还涉及权重量化、批处理和推测解码等方法。我们先了解它们各自在压缩权重、摊薄计算或减少主模型串行调用中的作用，再按实际瓶颈验证。量化后也要重跑关键题和模板测试，不能只检查模型是否成功加载。

从这里回看训练选择，长推理轨迹不仅增加训练数据与 rollout 成本，也增加每次使用成本。我们希望小助在需要时多算，在简单题上及时收束。推理能力与服务效率最终会在同一张成本质量图上相遇。

\textbf{停下来试一试} 用上式计算上下文从 4096 增到 8192 后的缓存量，再估算八个同时活跃会话。注明没有计算哪些开销。然后测一次真实服务，看估算与实际相差在哪里。
